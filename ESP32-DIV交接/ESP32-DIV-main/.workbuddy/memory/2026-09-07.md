### 现象
IDE 编译通过（51% / 3342336B = Huge APP 3.3MB 分区，非之前验证的 min_spiffs），点 Upload 报：
`Serial port COM11` → `A fatal error occurred: Could not open COM11, the port doesn't exist` → `exit status 2`。

### 端口扫描结论（ports.txt）
- **COM11 真实存在**，且 `USB\VID_303A&PID_1001&MI_00` = 乐鑫 ESP32-S3 原生 USB CDC 口，板子当时确实插着。

### 处置（已定位，待用户在硬件上执行）
1. IDE 内 Tools→Port 重选 COM11（列表可能过期）。
2. 最稳：手动进下载模式——按住 BOOT(GPIO0)→点 RST→松 BOOT，再点 Upload。
3. 兜底 esptool 直刷（板子手动进下载模式后，用 `--before no_reset`）：
   esptool：`AppData\Local\Arduino15\packages\esp32\tools\esptool_py\4.5.1\esptool.exe`

   （ESP32-DIV.ino.bootloader.bin @0x0 / .ino.partitions.bin @0x8000 / .ino.bin @0x10000）

### 硬件侧（v1 主板原理图）
- 充电链路是独立硬件：一片带 `TEMP/PROG/STDBY/CHRG` 引脚的线性锂电 IC（典型 TP4054/TP4056 或 clone，如 LTC4054 / LTH7），由 USB 5V 供电给电池充电。
- `CHRG` / `STDBY` 脚是开漏输出，硬件直驱 LED（或到测试点），**不受 ESP32 控制**。
- 电池电压经 R1/R2 分压后到 GPIO36 给 ESP32 ADC 采样，用来显示百分比。
- 板卡电源路径还含一颗 BSS123 (Q1) MOSFET 做 USB / 电池切换。

### 充电灯不亮的处置（按从软到硬）
1. 确认 board variant 用对：`shared.h` 里 `BOARD_ESP32_DIV_V1`（若误用 `BOARD_CYD` / 默认，`BATTERY_ADC_PIN=-1` ADC 读不到，但跟 LED 无关）。
2. 确认这是 **硬件 LED** 而不是屏上图标——屏上无充电标是 by-design，不是 bug。
3. 硬件排查：换一根确定能传电的 USB-C 数据线（用户反馈 COM11 上传 OK → 5V 应该到了）；量 USB-C VBUS 是否到 5V；量 PROG 电阻是否漏装（决定充电电流 + LED 行为）；电池过放/保护板锁死也会导致 CHRG 异常；某些板卡 CHRG LED 只在"实际充电"时亮，电池满就灭。

## 闪电标未出现 → 两个根因 + 修复（用户烧录后插 USB 仍不亮）

- **根因1（代码 bug）**：`statusBarTask` 的 `need` 重绘判断(原 756-771 行)未包含 `batteryIsCharging` 变化 → 插 USB 后若电量档位不跳变，状态栏永不重绘，闪电永远画不出。

  - `avail=0` → IP5306 不在 0x75 总线（硬件/地址/未上电）→ 查 IO8/IO9 走线或芯片批次。

## 现象：V2 插拔 USB 都会重启
- 根因：IP5306 在 VIN 插拔时于「电池BOOST↔VIN直供」间切换，3.3V 出现瞬态跌落；ESP32-S3 的 brownout 检测器（阈值~2.3~2.8V）被触发 → 硬复位。
- 铁证：`ESP32-DIV.ino:4512` 原作者用 `#if !BOARD_HAS_ESP32S3` 包住 `WRITE_PERI_REG(RTC_CNTL_BROWN_OUT_REG,0)`（注释：Weak USB/backlight load can brownout classic ESP32）→ V1 禁用了 brownout，V2/S3 漏了。
- 修复：`ESP32-DIV.ino` setup() 开头①加 `[RESET]` 复位原因打印（`esp_reset_reason()`，115200 看是 BROWNOUT 还是 POWERON）；②统一对所有板 `WRITE_PERI_REG(RTC_CNTL_BROWN_OUT_REG, 0)` 禁用 brownout（已确认 S3 头 `RTC_CNTL_BROWN_OUT_REG` 存在、bit30=BROWN_OUT_ENA、整体清零安全）。
- 验证：arduino-cli 编译 EXIT=0，零代码 warning；Sketch 1738285B(88%)。
- 注意：禁用 brownout 只是规避瞬态（原作者 V1 已用此法）；根治应在 IP5306 SYS 输出端加大 bulk 电容吸收切换毛刺。若烧后仍重启且 `[RESET]` 显示 POWERON/EXT，则不是 brownout，而是 EN 引脚被 VBUS 相关电路拉低 → 查硬件 EN 路径。
- 代码层已排除软件复位：全工程仅 `wifi.cpp:10121/10518` 两处 `ESP.restart()``，均与 USB 无关；V2 无 VBUS 检测、无 GPIO 中断绑 USB，固件不感知 USB 插拔。

## 关键硬件事实：IP5306 分 LED 版 / I2C 版，丝印无法区分
- **丝印 `IP5306` + 第二行批号（如 `7017 1HA`）两者完全一样**，标准版与 I2C 版(IP5306_I2C)顶面印字相同，第二行只是 serial code，**不能凭丝印判断版本**（来源 masterlexon / done.land）。
- 差异在功能/引脚：LED 版 pin2/3/4(L1/L2/L3) 驱动 4 颗电量 LED，无 I2C，不响应 0x75；I2C 版把 pin2/3/4 复用成 SCL/SDA/IRQ，地址 0x75，需 PCB 去掉 ISET 电阻 + 加 2.2K 上拉。
- V2 板按 I2C 版设计（原理图 IP5306 挂 IO8/IO9），若误焊 LED 版则 I2C 永远读不到(`avail=0`)。
- **判定法**：① 串口看 `[IP5306] avail=1`(I2C 且通) / `=0`(LED版误焊 或 KEY 未激活脉冲 或 上拉缺失)；② 不开机看板上有无 4 颗 IP5306 直驱电量 LED，有则基本是 LED 版。
- 坑：IP5306_I2C 上电后需对 KEY 脚发 30~2000ms 脉冲 I2C 接口才醒来；原固件从不碰 IP5306，KEY 若悬空可能一直睡，导致即使真 I2C 版也 `avail=0`。必要可在 `ip5306_begin()` 补 KEY 脉冲。
- 结论待用户确认：板上有无电量 LED / 串口 `avail=` 实测值，才能定"真实电量"走 IP5306 I2C 还是退回 ADC（V2 原理图可能未引分压电阻到 GPIO，需再核硬件）。
- **用户硬件确认（16:22）**：V2 原理图就是 I2C 版 IP5306 设计；板上 KEY 有按键（KEY 脚→10k 上拉→按键→GND，纯手动按键，不接 ESP32 GPIO，固件无法自动发 KEY 脉冲）。

## 示波器实测定案（18:17）：拔线时 VOUT 跌至 2V 持续十几 ms
- 用户实测：USB 拔出瞬间 IP5306 pin8(VOUT) 跌到 2V 持续十几 ms 再回升 → LF33 失稳 3.3V≈1.6V → 低于 S3 内部 POR 阈值(~2.4V) → 恢复供电后 POWERON 复位。**全案闭环。**
- 关键判断：健康 IP5306 切换空档应 <1~2ms；15ms 是 10 倍异常，**光堆电容填不平**（撑 15ms 需 ~7500µF 低 ESR）。必须先缩短空档。
- 两个嫌疑（各对应一个鉴别试验）：A=用户加的 VIN 侧电容拖延 VIN 跌落检测（缓跌形状吻合）→ 拆 VIN 侧电容重测；B=电池保护板被 BOOST 浪涌跳保护（DC 电源无保护板不重启的旁证）→ DC 电源替代电池重测空档。
- 行动计划：①DC 替代电池测空档；②拆 VIN 侧电容重测；③确认电池路径后，在电池插头/BAT 脚并 470~1000µF 防 RMS 保护跳；④VU5S 保留 470~1000µF 收尾。验收：拔线 3.3V 凹陷<0.3V、串口无新 [RESET]。
- 附：15ms 塌陷也解释 IP5306 I2C 卡死的另一半（失电器件钳总线）。
- **A/B 试验结果（18:39）：VIN 电容拆除与 DC 电源两种配置下空档依旧（十几 ms 跌 2V）** → 空档是 IP5306 自身 VIN 直通→BOOST 重配的固有特性（廉价充电宝 SoC），与环境无关，无法缩短。
- **最终修复方案（已给用户）：肖特基二极管电池直供旁路**——SS34 从 BAT+（IP5306 pin6/电池正）→ VU5S（5V 轨/LF33 输入），阳极 BAT。原理：拔线 VOUT 跌到 VBAT−0.45V≈3.45V 时二极管导通，电池直钳 VU5S 撑过 15ms；LF33 出 ~3.0-3.1V ≥ S3 规格下限；BOOST 恢复后自动反偏。正常/充电时均反偏零损耗。**警告：二极管禁止直接接 3.3V 轨**（充电时 4.2V−0.45=3.75V 会过压 3.3V 轨）。
- 附带收益：塌陷期间 ESP32 不再失电 → I2C 线不再被失电器件钳低 → IP5306 I2C 卡死频率应大幅下降。
- 验证：焊后复测示波器，预期 VU5S 钳在 ~3.45V 平台、3.3V 跌至 ~3.1V、无 [RESET]；0x75 失踪频率观察。可选加 220~470µF@VU5S 使衰减更平缓。

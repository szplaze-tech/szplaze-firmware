## 息屏保护：动态画面功能免息屏（15:10）

用户："在一些功能下 息屏保护应该是关闭的 比如有动态画面的地方"。

### 问题实质

低亮度电量屏是**整屏覆盖**的，而绝大多数功能屏（Packet Monitor 的实时曲线、
Scanner 的实时列表、BLE Scanner、SubGHz Jammer 的 RSSI 波形…）都在持续重绘自己。
超时一到就切到电量屏 ⇒ **活画面被整屏糊掉**，看起来像功能被中断。

### 实现：闸门（gate）模式，只在 utils 里加一处判断

沿用已有的 hook 风格（`screenSetWakeHook`），再加一个"是否允许息屏"的判断回调：

```
utils.h    typedef bool (*ScreenAutoOffGate)();  void screenSetAutoOffGate(fn);
utils.cpp  screenIdleTick(): 若 gate 返回 false → s_lastActivityMs = millis(); return;
ESP32-DIV.ino  注册 autoOffAllowed()
```

**为什么用回调而不是让 utils 直接读全局**：`feature_active` / `in_sub_menu` /
`active_submenu_items` 都定义在 `ESP32-DIV.ino`，utils.cpp 看不到（只有 shared.h:936 的
`extern bool feature_active`）。用回调把"上下文判断"留在应用侧，utils 保持与业务无关。

**关键细节：抑制期间必须持续刷新 `s_lastActivityMs`**。
否则用户在一个功能里待了 10 分钟 → 退出功能 → 下一拍 `screenIdleTick()` 拿 10 分钟前的
旧时间戳判定"早已超时" ⇒ **一退出就立刻黑屏**。刷新后退出功能会重新计满一个完整超时。

### 判断规则（`autoOffAllowed()`）

| 上下文 | 允许息屏？ | 理由 |
|---|---|---|
| `!feature_active` | ✅ | 主菜单 / 子菜单列表，静态 |
| `feature_active && !in_sub_menu` | ✅ | Settings / 关于页 —— 静态，且两者都已有唤醒重绘钩子 |
| `feature_active && in_sub_menu` 且名字在名单里 | ❌ | 动态画面功能 |
| `feature_active && in_sub_menu` 但不在名单 | ✅ | 静态功能屏 |

`in_sub_menu` 天然把 Settings/关于页与真功能屏区分开：这两者都是从
`handleButtons()` 的**非子菜单分支**进入的，不会把 `in_sub_menu` 置 true。

### 用"名字"而不是"下标"识别功能

`active_submenu_items` 指向当前子菜单的名字数组（`wifi_page0_items` 等），
`current_submenu_index` 是光标位置 ⇒ 直接 `strcmp` 名字即可，无需维护
(菜单号, 子菜单号, 页) 三元组的下标表。菜单改名时只需同步一处名单。

名单 `kDynamicScreenFeatures[]`（38 项，取自各 `*_submenu_items[]`）：
WiFi 10 项、Bluetooth 9 项、nRF24 5 项、SubGHz 4 项、Tools 2 项
（Serial Monitor / Touch Calibrate —— 后者尤其不能息屏，校准中途黑屏没法操作）、
IR 的 Record、RFID 5 项、GPS 2 项。

**未列入（照常息屏）**：Saved Profile、SD File Manager、Update Firmware、
Card Clone、Erase、Dump、Universal Controller。

## 电池电压检测 / 电量计算纠偏（18:20）

用户："电池电压检测和电量计算似乎不太准 现在是 75% 4.146v"。

**4.146V 按任何合理曲线都该是 94~95%，却显示 75%** —— 而 **75 恰好是 IP5306 的四档值
（0/25/50/75/100）之一**，这是决定性线索：**显示的电量来自 IP5306 回退，不是 ADC**。
顺着这条线找到三个真 bug：

### Bug 1（主因）：ADC 初检用"3 次里的最小值"

```cpp
uint32_t probeMv = analogReadMilliVolts(BATTERY_ADC_PIN);
for (i<2) { m = analogReadMilliVolts(...); if (m < probeMv) probeMv = m; }
```
原注释假设"瞬态只会把读数顶高"，所以取最小值挡向上尖峰。
但 **ESP32-S3 的 ADC 在 IDF 的 ADC1 锁被 WiFi 占用时会返回 0 附近** ——
3 次里只要有 1 次掉零，最小值就≈0 → 整次读数判为不可信 →
拒绝 → 退避 → **退回 IP5306 的四档值 → 屏上显示 75%**。

**修法**：改成 **5 次取中位数**（插入排序）。中位数对向上和向下尖峰都免疫。

### Bug 2：退避后立刻退回四档值 → 94%/75% 乱跳

**修法**：新增 `s_adcEverValid` / `s_adcLastVolt`。
ADC **曾经**读到过有效值之后，失败或退避期间**沿用它**，绝不退回 IP5306。
只有"从未成功过"（分压网络真坏）时才让 IP5306 兜底。退避 5000→2000ms。

### Bug 3：线性电压→电量映射（三处各写一份）

`map(v*100, 300, 420, 0, 100)` 在**三处重复**：`screenPercentFromVoltage()`(AOD)、
`drawStatusBar()`、`statusBarTask()`。锂电放电曲线在 3.7~3.9V 有平台区，
这 0.2V 里藏了约 40% 容量，线性必然把中段估高：

| 电压 | 旧(线性) | 新(锂电曲线) | 差 |
|---|---|---|---|
| 4.146V | 95 | **94** | -1 |
| 3.90V | 75 | **63** | -12 |
| 3.74V | 61 | **20** | **-41** |
| 3.60V | 50 | 3 | -47 |

→ 低电量区会**误以为还有一半电**，比高段偏差更危险。

**修法**：新增 `batteryPercentFromVoltage()`（utils.cpp/h），
21 点单节锂电 OCV 表 + 段内线性插值，**三处统一调用同一函数**（口径唯一）。
返回 `<0` 表示还没测到，调用方按 0 处理。

### 编译验证

`EXIT=0`，零告警。
```
Sketch 1777849 B (90%)   ← 上一版 1777749，+100 B
RAM    135196 B (41%)
```

**待实机验证**：屏上电量应约 94%（与 4.146V 自洽），不再出现 75%，也不再 94/75 乱跳。
若开 `DIAG_PRINTS_ENABLED`，`[IP5306]` 行的 `src=` 应为 `A`
（`I` 表示仍在走 IP5306 回退）。

### 检测项与判据

| 项 | 判据 |
|---|---|
| SD 卡 CS10 | `SD.begin(10, fspi, 4MHz)` → cardType + 容量 |
| CC1101 CS5 | 裸 SPI 读 PARTNUM(0x30)/VERSION(0x31)，全 0 / 全 FF = 无应答 |
| nRF24 ×3 | `radio.begin(&fspi)` + `isChipConnected()`（读 SETUP_AW，有效值 1..3）|
| 屏幕 ID CS17 | `tft.readcommand8(0x04, 1..3)`，ILI9341 应回 00 93 41 |
| 触摸 XPT2046 CS18 | 裸 SPI 读 Z1/Z2/X/Y/VBAT 五通道，全 0 或全 4095 = 无应答 |
| I2C 扫描 | 扫 0x03–0x77，列出应答地址 |
| PCF8574 按键 | 扫 0x20–0x27 + 读 5 个方向键电平（0=按下）|
| IP5306 0x75 | reg 0x70 bit3 充电 / reg 0x78 高 4 位电量 |
| 电池 ADC2 | `analogReadMilliVolts` × 6.6，**必须在 WiFi/BLE 之前采**（ADC1 会被无线占住）|
| BLE | `esp_bt_controller_init/enable` + 读 BT MAC，测完 disable 释放内存 |
| WiFi | mode(STA) + 同步扫描，`>=0` 即通过（0 只是周围无 AP），测完 WIFI_OFF |
| GPS 41/42 | UART2 9600 收 1.5 s 找 `$` 开头 NMEA；收不到 = N/A（多半没插模块）|

### ⚠ 两个实打实的坑（不是理论）

1. **SD 库会把 FSPI 抢回默认引脚**。`SDFS::begin()` 内部调 `spi.begin()`（无参），
   而 `SPIClass::begin()` 在四个引脚参数全 -1 时会把 S3 的 FSPI 强制绑到默认
   **SCK 36 / MISO 37 / MOSI 35** —— 那正是显示屏的总线，屏幕会当场挂掉。
   解法：SD.begin **之前**先 `fspi.begin(12, 13, 11, 10)`；`SPIClass::begin()` 开头
   `if(_spi) return;`（SPI.cpp:72）会保住这次的引脚配置。主工程 `sdSpiInit()` 是同一个套路。
2. **`TOUCH_CS` 不能当变量名** —— TFT_eSPI 的 `User_Setup.h:216` 已把它定义成宏，
   取名同会报 `expected unqualified-id`。本固件改用 `TS_CS`。

另外：`RF24::begin(_SPI*)` 只是 `_spi = spiBus`，**不会** reset SPI 引脚（RF24.cpp:945），
所以传自己的 FSPI 实例是安全的；反而 `begin(void)` 会调 `_spi->begin()` 覆盖引脚，别用。

## HardwareTest 改：按键触发改为边沿触发（16:10）

用户反馈「不要老是自动重复，按任意键再重跑」。

原 `loop()` 是每 500 ms 直接读 SELECT 电平，**没有边沿检测** → 按住不放就每 500 ms 重跑一次
（这正是"老是自动重复"的来源），而且只认 SELECT 一个键。

改动（仅 `loop()` + 新增 `anyKeyDown()`，其余不动）：
- 轮询降到 60 ms，读 UP/DOWN/LEFT/RIGHT/SELECT 五个键，任意一个按下即可触发
- 引入 `armed` 标志：**必须先全部松开才重新武装**，一次按下只触发一次
- `armed` 初值 false：上电要求先"全部松开"一次，避免开机压着键就误触发
- 简易消抖：判定按下后 delay(40) 复读，仍为按下才算
- PCF8574 地址只探测一次并缓存（`pcfBeginAny` 每次轮询扫 8 个地址太浪费）
- 屏幕底部提示由 `Sel key = run again` 改为 `Any key = run again`

## 主固件新功能：无操作自动熄屏（Settings → Screen Off）（17:10）

需求：Settings 里加一项，设定多久不操作就熄灭屏幕。

### ⚠ 最大的架构约束（决定了实现方式）

**每个功能都是 `while (!feature_exit_requested) { X::loop(); }` 阻塞在
`handleButtons()` 内部**（`ESP32-DIV.ino` 里十来处同构，如 `handleSettingsSubmenuButtons`）。
主 `loop()` 的尾巴（updateStatusBar / notificationTick）在功能运行期间**根本不执行**。
⇒ 息屏计时**不能只挂主 loop**，必须挂到"每条功能循环都会调用的输入读取函数"上。

### 实现结构

计时状态机在 `utils.cpp`（`s_lastActivityMs / s_screenOff / s_wakeIgnoreUntil`），四个出入口：

| 函数 | 作用 |
|---|---|
| `screenNoteActivity()` | 刷新活动时间戳（确认是有效操作时） |
| `screenIdleTick()` | 推进超时判断，到点灭背光。极廉价，可放紧循环 |

### 三个关键设计取舍（都写进注释了）

1. **"唤醒那一下"用时间窗而不是布尔标志**。同一次按下会被 `isButtonPressed` 和
   `isButtonPressedEdge` 连着问两遍，布尔标志会被第二问消费掉从而漏过闸门；
   改用 `s_wakeIgnoreUntil = millis() + 250ms`，250ms 内的输入一律丢弃。
2. **只关背光，不给 LCD 发 SLPIN**。LCD 不掉电就不用重 init，唤醒零延迟、无花屏风险；
   背光本来就是本板最大电流负载，省电收益的绝大部分在这里。
3. **默认值是 Off（永不熄灭）**，老配置文件没有 `screenOffIdx` 键 → 升级后行为不变，
   要用户自己去 Settings 里打开。

## 修 bug：息屏后点屏"像卡住" + 新增息屏低亮度电量屏（17:20）

用户反馈：「息屏后点击屏幕好像卡住了一样 屏幕动不了」。

### 🎯 根因（我的 bug，已定位）

`screenFilterInput()` 的唤醒分支**没有刷新活动时间戳**：

```cpp
if (s_screenOff) { screenWake(); s_wakeIgnoreUntil = millis()+250; return true; }
```

`s_wakeIgnoreUntil` 武装了，但 `s_lastActivityMs` 还是**几分钟前的旧值**。
唤醒后 `s_screenOff=false` → 下一拍 `screenIdleTick()` 拿旧时间戳算
`millis() - s_lastActivityMs >= timeoutMs` → **立刻又判定超时** → 再次 `screenSleep()`。
现象就是：点一下屏幕亮一瞬间又黑 → 用户感知为"卡住、屏幕动不了"。

**修法**：把 `screenNoteActivity()` 提到 `screenFilterInput()` 最前面无条件执行
——"能走到这个函数就说明确实有输入"，无论最终是否被丢弃都算一次操作。
一行修掉，同时让"按住不放"和"唤醒那一下"都正确刷新计时。

### 新增：息屏后显示低亮度电量屏（AOD）

- `shared.h`：`SCREEN_OFF_DIM_LEVEL`(默认 24，"最低亮度")、`SCREEN_OFF_AOD_REFRESH_MS`(2000)
- `utils.cpp`：`screenDrawAod(bool force)`
  - 电池外框 150×76 居中（`bx=(W-150)/2-5, by=H/2-38` → 40..190 / 122..198），右侧正极凸点
  - 电量条按百分比填充，>20% 绿、否则红（与状态栏口径一致）
  - **百分比用 font 6（24×48px/字）**，`MC_DATUM` 居中压在电池框正中
  - 有外部电源时在电池**上方**画 2 倍大黄插头（`px=W/2-21, py=by-58`）
  - **只在数值变化时重画**（`s_aodPct`/`s_aodPlug` 比对 + `force`），避免每 2 秒整屏闪
- `screenSleep()`：先 `screenDrawAod(true)` **再**降亮度（避免"先暗一下再亮"的闪动）
- `screenIdleTick()`：睡眠期间每 2s 校一次电量/插头。数据来源 `currentBatteryVoltage` /
  `usbPowerPresent` —— **`statusBarTask` 是独立 FreeRTOS 任务，即使主流程被功能屏
  的 while 卡住这两个全局量仍在更新**，所以 AOD 是活的

### 唤醒重绘机制（屏幕被 AOD 整屏覆盖过，必须重绘）

| 机制 | 用途 |
|---|---|
| `screenSetWakeHook(cb)` | 应用注册"唤醒后整体重绘当前界面"。主固件实现 `onScreenWakeRepaint()` |
| `screenConsumeRepaintRequest()` | 标志式，给"能自行重绘的功能屏"在循环里自查（消费即清） |

- `onScreenWakeRepaint()`：`feature_active` 时**直接返回**（标志留给功能屏）；
  否则清标志 + `drawStatusBar(...,true)` + `menu_initialized=false, last_menu_index=-1`
  → `displaySubmenu()` 或 `displayMenu()`。已确认这两个函数**不读输入、不阻塞**，
  从输入路径里调用安全。
- `AppSettingsUI::loop()` 开头消费标志 → `drawAll()`（Settings 界面覆盖到了）
- **关于页**原本是内联静态绘制，已把绘制块抽成 `drawAboutPage()`，
  循环里消费标志重绘（改名 + 拆函数的机械改动）

### 唤醒闸门顺序修正

`screenWake()` 内部会调 hook，hook 可能间接读输入。所以把
`s_wakeIgnoreUntil = millis()+250` **提到 `screenWake()` 之前**执行，
否则 hook 执行期间读到的按键会被当成真实按下。

## 三轮修复：数字不居中 / 没有百分号 / 应该区域刷新（17:45）

用户反馈三点，其中**前两点是同一个根因**，都是 TFT_eSPI 字体的坑。

### 🎯 根因 1：`%` 画不出来 —— font 6 是"数字专用"字体

把 `TFT_eSPI/Fonts/*.c` 的 `chrtbl_fXX[96]` 全部解析出来的实测结果：

| 字号 | 文件 | 真实字符 | 有 `%`？ |
|---|---|---|---|
| 2 | Font16.c | **全 ASCII 96 个** | **有** |
| 4 | Font32rle.c | **全 ASCII 96 个** | **有** |
| **6** | Font64rle.c | **只有 `- . 0-9 : a m p`**，其余 **80 个码位指针全部指向 `chr_f64_20`（空格）** | **没有** |
| 8 | Font72rle.c | 只有 `- . 0-9 :` | 没有 |

有 `%` 的那些码位指针数是 80 个 → 说明 font 6/8 是给"大号数字/时钟"用的**数字专用字体**。
⇒ `snprintf("%d%%")` 生成 "75%"，font 6 里 `%` 映射成空格字模，**画出来是空白**。

### 🎯 根因 2：数字不居中 —— `uiPrint` 的 ASCII 路径不认 datum

`i18n.cpp` 的 `uiPrint(const char*)`：

```cpp
if (g_lang != LANG_ZH || isAsciiOnly(t)) { tft.print(t); return; }   // ← 走这条路
drawMixed(...);   // 只有含汉字时才按 s_datum 算 dx/dy
```

而 **TFT_eSPI 的 `print()`/`write()` 完全不理会 `setTextDatum`**，只按 `cursor_x/cursor_y`
左上角画。所以 `uiSetTextDatum(MC_DATUM)` + `uiSetCursor(中心)` + `uiPrint("75%")`
实际把文字**左上角**放在电池中心 → 看起来偏右下。

**附带**：各字体的字宽是**比例字宽**（`widtbl_fXX[]`），不是等宽。
font 6 数字 27px/位、font 4 的 `%` 21px/位 —— 所以居中必须实测宽度，
不能用"字数 × 固定值"估算（i18n 层内部的 `fontWidthOf()` 就是固定值近似）。

### 修法

```cpp
// 数字 font 6（大：48 高 / 每位 27 宽），'%' 换 font 4（26 高 / 21 宽）拼成上标
const int wNum = tft.textWidth(num, 6);  // textWidth(s,font) 按 fontdata[font].widthtbl 查表，可信
const int wPct = tft.textWidth("%", 4);
const int x0   = x + AOD_BAT_W/2 - (wNum + 2 + wPct)/2;
uiSetTextDatum(TL_DATUM);                // 显式定死，print 路径只认左上角
uiSetCursor(x0, yNum);          uiSetTextFont(6); uiPrint(num);
uiSetCursor(x0+wNum+2, yNum+6); uiSetTextFont(4); uiPrint("%");   // % 略下移，上标观感
```
- 电池宽度 **120 → 132**（内框 120px）：最宽情况 `"100%"` = 81+2+21 = **104px** ✓
- 电量未知时（pct<0）只画 `--`，**不画 `%`**，避免出现 `--%`
- 字体切换一律走 `uiSetTextFont()`（保持 i18n 镜像状态同步），不能用裸 `tft.setTextFont()`

### 修法 3：区域刷新（用户指出"电池数字变化不该全屏刷新"）

原来 `screenDrawAod()` 一进来就 `fillScreen(BLACK)`，**任何变化都整屏清 + 重画**。
拆成三个区域函数：

| 函数 | 作用 |
|---|---|
| `aodDrawFrame()` | 外框 + 顶部正极凸点（只在整屏重画时用） |
| `aodDrawValue(pct)` | **只重画电池框内部**：用内缩 2px / 半径 8 的 `fillRoundRect` 清底（正好避开半径 10 的外框描边），再画电量条 + 数字 |
| `aodDrawPlug(on)` | **只重画插头区域**（44×52），`on=false` 时只清黑 |

`screenDrawAod(force)` 判定：
```
first = (s_aodPct == -2)      // 还没画过
whole = force || first        // 整屏
whole || pct 变了 → aodDrawValue
whole || plug 变了 → aodDrawPlug
都没变 → 直接 return（连清屏都不做）
```
⇒ 电量跳变只重画电池内部；插拔 USB 只重画插头那块；10s 兜底整屏重画仍保留。

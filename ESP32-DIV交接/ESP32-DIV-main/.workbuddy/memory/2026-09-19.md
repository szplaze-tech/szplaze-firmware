## 红外发射/接收引脚确认（15:53）

用户问红外引脚。**shared.h 的 V2 分支当前生效值**：

| 信号 | 引脚 | 定义位置 | 备注 |
|---|---|---|---|
| 红外**发射** TX | **GPIO46** | `shared.h:683` | 原 GPIO14（= nRF24 #3 的 `CE_PIN_3`，IRsend 翻转会拉低 CE） |
| 红外**接收** RX | **GPIO40** | `shared.h:663` | 原 GPIO21（= nRF24 #3 的 `CSN_PIN_3`，且接收在该脚挂 CHANGE 中断） |
| 载波 | 38 kHz | `IR_DEFAULT_KHZ` | |

使用方式（`ir.cpp:61-63`）：`kRecvPin = IR_RX_PIN` / `kSendPin = IR_TX_PIN`，
`IRrecv s_recv(kRecvPin)` / `IRsend s_send(kSendPin)`（IRremoteESP8266 库）；
进入红外功能时 `pinMode(kRecvPin, INPUT_PULLUP)` + 挂 CHANGE 中断、`pinMode(kSendPin, OUTPUT)`，
退出时 `disableIRIn()` 关闭中断。至此红外与 2.4G **完全解耦**。

### ⚠ 待用户确认的一处歧义（重要，别忽略）

对话历史里用户说过 **"那你就改成 io40 吧"**，且该句的上下文是**发射**
（上一句是"把发射二极管的 io 打算换成 IO46"）。但**代码里 40 给了接收、46 给了发射**。
已在回复中请用户确认；若他要"发射用 40"，则需要：
1. 对调 `IR_TX_PIN` / `IR_RX_PIN`，且 40 给发射后**接收只能挪到 GPIO39**（板上唯一空闲脚）；
2. 好处是发射离开 strapping 脚 46，硬件接线约束随之解除。

### GPIO46 的硬件铁律（strapping 脚）

禁止 **VCC → IR LED → 限流电阻 → GPIO46** 的灌电流/上拉接法：上电瞬间该脚被拉高，
会**禁用 ROM 启动日志**，并可能与 GPIO0（BOOT 键）组成无效组合而**进不了下载模式**。
必须用**低侧驱动**：`GPIO46 → R1 → NPN 基极`；`3V3 → IR LED → 限流 R → NPN 集电极`；
`NPN 发射极 → GND`。
软件侧是安全的（IRsend 只在进入功能时 `pinMode(OUTPUT)`，上电期间该脚高阻/内部弱下拉）。

接收侧：IR 接收头（VS1838B 类，开漏输出）OUT 直连 GPIO40，代码用 `INPUT_PULLUP` 正好匹配。

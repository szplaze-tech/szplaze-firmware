## 电量百分比"跳动"根因 + 修复（本次完成）
- 用户复测：电量百分比显示老跳动（之前 `--` 已修好，这次是算出来的值在抖）。
- 根因：读数管线 `readBatteryVoltage()`（utils.cpp:908）原本首次采样后 `s_adcNextTryMs` 不再推进 → **之后每调用一次就重采 21 次 ADC**（5 中位数 + 16 均值），返回裸实时平均电压，**跨调用零时间滤波**。
- 叠加两个噪声源：① ESP32-S3 ADC 固有噪声；② 工程常驻 `WifiScan::startBackgroundScanner()`/`BleScan::startBackgroundScanner()`（setup:4937-4938）周期拉电流 → 电池分压随负载起伏。
- 放大机制：状态栏 `statusBarBatteryMeaningfulChange`（utils.cpp:1045）在 **≤25% 低电量区任意 1% 变化即重绘**；用户电池实测~3.57V 经 OCV 曲线只映射到 ~2~3%（落进敏感区）。裸电压 ±mV 抖 → 百分比 ±1% → 肉眼跳动。
- 修复（仅 `readBatteryVoltage()` 一处）：新增 `s_emaVolt` 静态 EMA；有效读数分支改为 `s_emaVolt = s_emaVolt*0.6 + adcVolt*0.4`（α=0.4，时间常数≈2.5s），并加 `s_adcNextTryMs = millis()+1000` **采样节流到 1Hz**（采样间返回缓存 EMA）。副作用正面：省掉每帧 21 次采样的 CPU 开销。所有调用点（状态栏/AOD/BT/WiFi/IR 等）自动受益。
- 编译 EXIT=0，FQBN 同前，固件 1,794,597B (57%)。用户自行烧录复测；必要时可调 α 或采样间隔进一步加平滑。
- 注：未引入 A↔I 源切换（本板 IP5306 不在线，ever-valid 后恒走缓存，不会跳源）。

## 电量"进功能界面就假放电 38%→24%"根因 + 修复（本次完成）
- 用户复测：加了 EMA+1Hz 后还是剧烈跳——进功能界面（点亮屏幕/拉起 RF）电量从 38% 掉到 24%。
- 根因不是噪声，是**带载端电压跌落被陡峭 OCV 曲线放大**：进功能界面负载电流上升 → 电池端电压真实跌落约 30mV；OCV 曲线在 3.76~3.80V 段极陡（约 32mV≈14%），于是显示 38%→24%。这是假放电（SoC 不该因开背光下降）。
- OCV 曲线核对：`batteryPercentFromVoltage()`（utils.cpp:571）表 3.79V→35%、3.76V→25%；38%≈3.796V，24%≈3.764V，落差正好 ~32mV。
- 修复（仅 `readBatteryVoltage()` 一处，新增 `s_peakVolt` 峰值保持）：有效读数分支改为先算 EMA(α=0.4)，再 `s_peakVolt` 取近期最高平滑值——回升/充电立即跟高，带载/放电极慢衰减（系数 0.003，~330s 时间常数）屏蔽短暂负载跌落；`s_adcLastVolt = s_peakVolt`。效果：进功能界面 30s 峰值仅回落 ~1%，退出立即恢复；真实放电经慢衰减反映。
- 编译 EXIT=0，FQBN 同前，固件 1,794,661B (57%)。用户自行烧录复测。

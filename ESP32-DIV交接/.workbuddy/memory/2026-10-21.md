## IR 功能按键进入蜂鸣长响（2026-10-21）
- 现象：按键方式进入 IRremote 蜂鸣器一直响，触屏进入正常。
- 根因：ir.cpp 三个 loop()（1219 抓取 / 1927 信号库 / 3044 万能遥控）用 isPhysicalButtonPressed()/isTouchNavButtonPressed() 裸读按键，绕开 isButtonPressed()，而 uiBeepPoll() 只在 isButtonPressed() 和主 loop 里。菜单层按 SELECT 的沿启动 uiBeep（LEDC 持续出波）后，IR 循环内无人关音 → 响到退出功能。触屏进入无按键沿、不启动蜂鸣。
- 修复：featureExitButtonPressed()（ino ~808）开头补 uiBeepPoll()——该函数是所有功能 dispatch while 循环每拍必调的钩子，一处兜底覆盖全部绕路功能页。
- 背景：LEDC 出波后必须 ledcWriteTone(ch,0) 才停；uiBeep 只启动、uiBeepPoll 只负责关。

## 蜂鸣长响全工程审计 + esp_timer 硬兜底（2026-10-21）
- 用户反馈多模块复现"按键进功能蜂鸣长响"。审计：ino 共 70 段 dispatch while，68 段循环体调 featureExitButtonPressed（昨天补丁后已覆盖）；2 段裸奔——ino:832 Ducky（ducky.cpp 仅 119 行一处 isButtonPressed 是打字键值查询，loop 无每帧轮询）+ ino:4575 Settings 屏（内部每帧 isButtonPressed，实际已覆盖）。ir.cpp 三个 loop 属裸读按键类。历史结论：补丁前所有不自己 poll 的功能全都会长响。
- 根治：utils.cpp uiBeep()/uiBeepSelfTest() 挂 esp_timer 一次性定时器（ESP_TIMER_TASK 任务上下文回调 ledcWriteTone 0 + ledcDetachPin），esp_timer_stop+start_once 重挂；与任何循环配合无关，机制上消灭该 bug 类。字段顺序已对照 core 2.0.10 esp_timer.h 核实。uiBeep 内部 ms==0 兜底 45→25 同步修正。
- uiBeepPoll() 常规路径保留；s_uiBeepArmed 幂等防双关。

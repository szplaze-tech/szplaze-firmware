# 2026-09-11 工作日志

## 充电芯片 IP5306 → TP5400 改造（规划阶段）

用户决定把充电芯片从 IP5306（I2C 版）换成 **TP5400**，电池电量改用**分压电阻测电压推算**。

### TP5400 关键资料（已核实 datasheet）

SOP-8 引脚：
1. **VOUT** — 5V 升压输出检测
2. **CHRG** — 充电中指示，**漏极开路，充电时内部拉低**，否则高阻态
3. **PROG** — 充电电流设定（1.2kΩ ≈ 1A；断开 = 停止充电）
4. **STDBY** — 充满指示，充满时内部拉低，否则高阻态
5. **VCC** — 充电输入 5V
6. **BAT** — 电池正极（浮充 4.2V）
7. **GND**
8. **LX** — 升压开关节点

**无 I2C**，但 CHRG/STDBY 两个开漏脚可直接给 MCU 读状态——检测比 IP5306 的 I2C 更简单可靠。

### 改造方案

**硬件**：TP5400 CHRG(脚2) → ESP32 空闲 GPIO + **INPUT_PULLUP**（低电平 = 充电中）。可选：STDBY(脚4) → 另一 GPIO（低 = 已充满）用于区分"充电中/已充满"。

**固件**（待用户定 GPIO 后实施）：
1. 新增 `BATTERY_CHG_PIN` / `BATTERY_STDBY_PIN` / `BATTERY_CHG_ACTIVE_LOW` 宏；
2. 新增充电器类型宏（`BATTERY_CHARGER_TP5400` / `_IP5306`），充电检测分支：TP5400 走 GPIO、IP5306 走 reg0x70 bit3，两种硬件共存兼容；
3. 电量：`BATTERY_ADC_PIN`(GPIO2) 分压读数 → 电压 → 百分比。现为线性 `map(3.0..4.2V → 0..100%)`，可改**锂电池分段查表**（线性在中段偏高约 20 个百分点：3.7V 线性给 58%，实际约 35%）。

### ⚠️ 重大风险：TP5400 升压仅 5V/1A，IP5306 是 2.4A

系统峰值（S3 + TFT + CC1101 + nRF24 + WiFi/BLE 射频发射）可能接近或超过 1A → 过流/电压跌落，**可能恶化此前已修复的"拔 USB 重启/塌坑"问题**。换芯后必须复测该场景，并核算峰值电流；必要时保留更大输出电容或选 2A 级替代（如 IP5306/IP5328 或 TP5400 之外更高规格）。

### 待用户确认
1. CHRG 接哪个 GPIO？（阻塞项）
2. STDBY 是否也接（区分充满）？
3. 分压电阻是否沿用现板（GPIO2，实测 6.6:1）还是重新设计 → 决定 `BATTERY_VDIV_MULT` 校准值；
4. 电量曲线用线性还是分段查表。

### GPIO42 能否用？（14:26）

- 工程**零引用**、**非 strapping 脚**、是 S3 默认 JTAG 脚之一(**MTMS**)；
- **默认 eFuse 未烧录时 JTAG 走内置 USB Serial/JTAG(GPIO19/20)，不占用 GPIO39-42** → 可自由使用 ✓；
- 唯一约束：日后若改用**外部 JTAG 调试器**（PAD JTAG，接 MTDI/MTCK/MTMS/MTDO），GPIO39-42 被征用，CHRG 需换脚。
- 候选脚优劣：**GPIO24(最保险,无任何牵连) > GPIO41/42(默认不占,除外部JTAG) > GPIO46(strapping,严禁外部上拉)**。

**状态（17:34）：用户已知晓各候选脚差异，TP5400 改造与 CHRG/STDBY 脚号暂缓，待其后续定夺。**

### GPIO46 能否用？（11:47，查 S3 datasheet 第3章）

ESP32-S3 的 4 个 strapping 脚：`GPIO0`(弱上拉, Boot 模式) / `GPIO3`(浮空, JTAG 源) / `GPIO45`(弱下拉, VDD_SPI 电压) / **`GPIO46`(弱下拉, ①Boot 模式 ②ROM 消息打印控制)**。

- **技术上可用**：datasheet 明确"strapping 脚在复位采样后即释放为普通 IO"。
- **成立条件：不能加外部上拉电阻**。原理：strapping 只在**复位瞬间**被 latch 采样，那一刻固件尚未运行、GPIO46 = 芯片默认弱下拉 = 0 → 正常 SPI Boot + ROM 日志使能；固件运行后 `pinMode(46, INPUT_PULLUP)` 才生效，用于读 CHRG（开漏）完全够。
- **不成立的情形**：若 PCB/外加了上拉电阻到 46 → 上电瞬间 46=1 → ①**ROM 启动日志被禁用**（`ESP-ROM:.../mode:DIO` 等全没了，排查会瞎）②下载模式风险：GPIO0=0(按BOOT) + GPIO46=1 属 datasheet 明示的**无效组合**"should be avoided"，可能进不了下载。
- **结论**：GPIO46 可用但受限（严禁外部上拉）；**仍首选 GPIO24/41/42**。若板上只引出 46，则按"仅用内部上拉"实施。
- **推荐给 TP5400 CHRG：GPIO24**（普通脚、非 strapping/非 JTAG、零引用）；次选 41/42；若还要 STDBY 则用另一个空闲脚。
- CHRG 是**漏极开路**输出 → GPIO 配 `INPUT_PULLUP`，**低电平 = 充电中**。

## 2.4G 菜单：每个子功能用的 nRF24 模块与用法（17:34 全量梳理）

菜单项（ESP32-DIV.ino:97-119）：BLE Jammer / Scanner / Proto Kill / ESB Sniffer / ESB Replay / MouseJack Scan / MouseJack Inject。（同菜单下还有 BLE Spoofer、Sour Apple、AirTag Spoofer/Sniffer、BLE Skimmer、BLE Sniffer、BLE Scan —— 这些走 **ESP32-S3 内置 BLE**，不用 nRF24。）

| 子功能 | namespace | 用的模块 | 驱动方式 | 干什么 |
|---|---|---|---|---|
| **BLE Jammer** | BleJammer (3122) | **#1+#2+#3 三颗并发** | RF24 库 | 三颗各在一组 BLE 广播信道发射**常量载波**阻塞 BLE |
| **Scanner** | Scanner (4032) | **#3** | **自写寄存器驱动** | 逐信道读 **RPD**(0x09) 载波检测位，画柱状图 |
| **Proto Kill** | ProtoKill (4997) | **#1+#2+#3 三颗并发** | RF24 库 | 机制同 BLE Jammer：三组信道 `startConstCarrier` 常量载波 |
| **ESB Sniffer** | EsbSniffer (5424) | **#3** | 自写寄存器驱动 | 捕获 Enhanced ShockBurst 包，显示地址+载荷；含 SD SPI 总线切换 |
| **ESB Replay** | EsbReplay (6286) | **#3** | 自写寄存器驱动 | 重放嗅探到的 ESB 包 |
| **MouseJack Scan** | MouseJack (7123) | **#3** | 自写寄存器驱动 | 扫描可注入的 nRF24 无线鼠标 |
| **MouseJack Inject** | MouseJackInject (8008) | **#3** | 自写寄存器驱动 | 注入鼠标报文（MouseJack 攻击） |

**关键点**：
1. **Proto Kill = 三颗全用**（不是单颗），与 BleJammer 同一机制；
2. 三颗的信道分组（BleJammer/ProtoKill 共用，bluetooth.cpp:3137-3139 / 5018-5020）：
   - radio1 → `{2,5,8,11}` ≈ **BLE 广播信道 37**(2402MHz)
   - radio2 → `{26,29,32,35}` ≈ **BLE 广播信道 38**(2426MHz)
   - radio3 → `{80,83,86,89}` ≈ **BLE 广播信道 39**(2480MHz)
   （BLE 广播只在 37/38/39 三信道，故三颗各堵一个 → 单颗做不到）
3. `configureRadio()` 设置：`stopListening` / `setRetries(0,0)` / `setPALevel(RF24_PA_MAX,true)` / `setDataRate(RF24_2MBPS)` / `setCRCLength(RF24_CRC_DISABLED)` / `setAutoAck(false)` + 每信道 `startConstCarrier()`；
4. **只有 BleJammer/ProtoKill 用 RF24 库**；Scanner/ESB×2/MouseJack×2 这 5 个都**自己 bit-bang SPI 寄存器**（`SPI.begin(NRF24_SPI_SCK/MISO/MOSI/SS)`=12/13/11/4 + `getRegister/setRegister`，片选走 `NRF24_SCAN_CE/CSN`=#3 的 GPIO14/21）；
5. ESB Sniffer 有 **SPI 总线切换**（`esbSwitchToSdSpi()` → `SPI.begin(SD_SCLK, SD_MISO, SD_MOSI, SD_CS)`）：因 SD 卡与 nRF24 共享同一条 SPI，访问 SD 时重新绑定引脚。

## MouseJack Scan / Inject 实现要点（17:48）

- **Inject 注入的是「未加密 Logitech Unifying 键盘帧」(BN-0002 风格,10 字节 HID report)，不是鼠标动作**：`injSendHidFrame()`（bluetooth.cpp:8555）组帧 `{0x00,0xC1,modifier,key,0...}+校验和`，`injTransmitString()` 逐字符 key-down/key-up。
- 预设 payload 6 条（8061-8068）：`"hello" / "Hello World!" / "test123" / "ESP32-DIV" / "CiferTech" / "admin"` —— 测试建议先用 `hello`。
- 抗跳频：每字符**重复发 3 次、轮换 3 个邻近信道**（`(ch, ch+1, ch+83)%84`）；目标 dongle 会跳频，故多信道重发。
- 目标来源：**先跑 MouseJack Scan**，扫到的设备存 `g_mjShared[]`，进 Inject 时同步为 `s_targets[]`（8334）。
- 操作：Prev/Next 选目标、Next Payload 切 payload、**UP 键 = Fire**（`injToggleScanOrFire()`）。
- 前置条件：目标必须是**无加密的 nRF24 类 Logitech Unifying 设备**（Bolt/加密款规定失败；BLE 蓝牙鼠标根本扫不到）；鼠标要活跃发包；需靠近接收器。
- **合规**：仅限自有设备测试，对他人设备注入 HID 属未授权访问，违法。

## MouseJack 测试受阻（17:51）

用户手上的鼠标是**神舟无线 2.4G 鼠标**（非蓝牙、非 Logitech Unifying）→ **不能作为 Inject 目标**：
- 代码的厂商分类只认 **Logitech / Microsoft / Amazon**（bluetooth.cpp:7404-7424），其余一律归 `Other`(显示 "nRF HID") 且 **vulnerable=false**（不标为可注入）；

## ESB Sniffer / ESB Replay（18:02）

**ESB = Enhanced ShockBurst**，nRF24L01 的专有链路层协议（自动应答 ACK、自动重传、带 5 字节地址的包）——所有 nRF24 类设备（无线键鼠、遥控、玩具、传感器）都跑它。两个功能都基于 **nRF24 #3** 的广播接收。

| | **ESB Sniffer**(5424) | **ESB Replay**(6286) |
|---|---|---|
| 收发 | **只收** | 收 **+ 发**(重放) |
| 原理 | `RX_ADDR_P0={0xAA×5}` 广播接收、`EN_AA=0`、`SETUP_AW=3`、`RX_PW_P0=32`、`CONFIG=0x0B`；**80ms 跳频**扫信道 | 同样广播接收捕获，`rpStoreCapture()` 存**内存最多 8 条**(`kRpMaxCaptures`) |
| 存放 | **持续写 SD 卡** `/esb/esb_*.txt`（2s 周期 flush，`kEsbDir`) | 内存 8 条，长按 DOWN 清空 |
| 发送 | — | `rpPlaySelected()` → `rpConfigureTx(ch)` + `rpWritePayload()`（`0xA0`=W_TX_PAYLOAD）+ CE 脉冲，**每条重发多次**(`kRpReplayBursts`) |
| 按键 | UP=开关跳频、DOWN=开关 SD 日志 | LEFT/RIGHT=选捕获项、DOWN=布防捕获(长按清空)、**UP=重放选中项** |
| 用途 | 协议分析/取证（看设备在传什么、用什么地址/信道） | 重放攻击验证（如重放遥控指令，测自有设备抗重放能力） |

**注意**：两者都依赖 nRF24 #3 —— 板载 nRF24 若仍有问题，这两个功能同样无输出。目标设备必须是 nRF24 类私有 2.4G 设备（WiFi/BLE 不行）。Replay 属重放攻击，仅限自有设备。
